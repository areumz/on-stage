# ON-STAGE 1차 구현 계획 — 요약

> 이 문서는 `docs/plan.md`(superpowers `writing-plans`로 생성한 상세 구현 계획)의 요약본이다.

**Goal**: 가상 레이블 STAGE.ONE 플랫폼 1차 — A탭(팬: 궤도 메인 + 아티스트 스크롤 스토리) + B탭(관계자: 로그인/대시보드/무대 연출 3D 툴)을 Vercel 배포까지 완성한다.

**Architecture**: Next.js App Router 단일 앱. 데이터는 mock JSON → Route Handlers(`/api/*`) 경유로만 클라이언트에 전달. 3D는 섹션별 독립 R3F Canvas, 인증은 하드코딩 계정 + 쿠키 + 라우트 가드.

**Tech Stack**: Next.js(App Router), TypeScript, Tailwind CSS, React Three Fiber + drei, Recharts, Vitest(로직 테스트 전용).

---

## Global Constraints (모든 태스크에 적용)

- TypeScript strict 모드
- 3D는 처음부터 R3F로 작성 (바닐라 → 리팩토링 금지)
- 클라이언트는 API Routes 경유로 조회 (mock 데이터 직접 import 금지)
- **TDD는 로직 레이어만** (인증, API Routes, 데이터 변환). 비주얼 레이어(R3F/셰이더/레이아웃)에 형식적 테스트 생성 금지 — 브라우저 시각 검증으로 대체
- 1차는 데스크톱 기준 (반응형은 2차)
- Out of Scope (선제 구현 금지): 완전한 인증 시스템, i18n, 모바일 반응형, 실 결제/예매, 백엔드 서버 분리
- 커밋 컨벤션: Conventional Commits

## Task 목록

> 각 태스크의 **검증 노트**는 계획대로 구현한 뒤 브라우저 시각 검증·코드 리뷰·품질 게이트에서
> 실제로 발견하고 고친 것들이다. 계획 문서 자체에 대한 검증은 맨 아래 Self-Review 참고.

### Task 1 — 프로젝트 세팅
`src/` 구조 정리, 디자인 토큰 등록, 폰트(영문/한글 세리프) 추가, Vitest 세팅. 이후 모든 태스크의 기반이 되는 작업.

### Task 2 — 타입 + mock 데이터 + API Routes (TDD)
`Artist`, `Metrics` 타입 정의 및 mock JSON 작성. `/api/artists`, `/api/metrics` Route Handler를 TDD로 구현. 클라이언트는 이 API를 통해서만 데이터에 접근한다.

**검증 노트**
- JSON을 타입 없이 그대로 반환하던 원안은 데이터와 타입이 조용히 어긋나도 아무도 눈치채지 못했다. `const artists: Artist[]` 한 줄로 묶어 빌드가 스키마 드리프트를 잡게 하고, 필드를 지우거나 타입을 바꿔 실제로 컴파일이 깨지는지 확인했다. 다만 초과 필드는 잡히지 않는다는 한계(TypeScript의 초과 속성 검사는 객체 리터럴에만 적용)까지 함께 기록했다.
- 리뷰에서 궤도 인덱스를 `number` 대신 리터럴 유니온으로 좁히자는 제안이 나왔지만 실제로 넣어보니 빌드가 깨졌다. JSON import의 숫자는 `number`로 넓혀 추론되기 때문이라, 근거를 확인한 뒤 기각했다.
- 유닛 테스트는 핸들러 함수를 직접 호출할 뿐 프레임워크가 URL을 라우팅하는지는 증명하지 않는다. 프로덕션 서버를 띄우고 curl로 전체 목록·단건 조회·없는 slug 404를 한 번 더 확인했다.

### Task 3 — 공통 헤더
A/B 탭 토글과 로고 헤더를 모든 화면에서 공용으로 쓸 수 있게 컴포넌트화.

**검증 노트**
- 목업 이미지를 픽셀 단위로 디코딩해 실측한 결과, 원안의 pill 형태는 목업과 다른 컨트롤이었다 — 테두리와 채움 사이 간격이 0이고, 컨테이너에는 배경이 없으며, 두 탭이 맞닿는 안쪽 모서리는 직각이다. 구조를 맞추자 비활성 텍스트가 페이지 배경 위에 직접 놓여 명암비가 4.48:1로 AA에 미달했고, 텍스트 색을 7.01:1까지 올려 함께 조정했다.
- 원안의 단일 톤은 B탭 라이트 배경에서 명암비 1.41:1로 사실상 보이지 않았다. 톤과 탭은 독립된 축이라(무대 연출 화면은 staff 경로지만 다크 톤이다) 경로로 톤을 유도하지 않고 호출부가 넘기도록 했다.
- 목업의 브랜드 보라가 디자인 토큰과 다르다는 것도 실측으로 드러났다. 다만 목업 쪽 색은 이미 다른 아티스트의 시그니처 컬러라 채택하면 궤도 화면에서 충돌하므로, 토큰을 유지하고 목업을 낡은 것으로 판단했다.

### Task 4 — A탭 레이블 메인 (궤도)
`docs/mockups/a-depth1-orbit.png` 기반. 궤도 R3F 씬 + 하단 NOW 티커. 아티스트 노드 클릭 시 투어 페이지로 이동.

**검증 노트**
- 노드의 궤도 반지름 분포는 목업과 다르게 두기로 판단했다. 각도는 목업과 정확히 맞췄지만, 목업처럼 6개를 바깥 궤도에 몰면 안쪽 궤도가 늘 비어 "3중 동심원"이라는 비주얼 컨셉 자체가 죽는다. 브라우저에서 실제 렌더링을 보고 데이터를 그대로 두기로 결정했다.
- 응답 상태를 확인하지 않고 곧바로 JSON으로 파싱하던 코드에 상태 검사와 에러 로깅을 넣었다. 실패해도 원인 없이 빈 화면만 남던 것이 이제 콘솔에 드러난다. 티커 항목의 key도 배열 인덱스에서 slug로 바꿨다.
- 콘솔에 계속 뜨던 Three.js deprecation 경고는 추적해 보니 R3F와 three 버전 조합의 내부 렌더 루프 문제였고 이 태스크가 작성한 코드와 무관했다. 고치지 않고 의존성 업그레이드 시 확인할 항목으로 남겼다.

### Task 5 — 아티스트 투어 페이지 Hero
`docs/mockups/a-depth2-hero.png` 기반. 거대 세리프 타이포 + 셰이더 배경. 아티스트별 시그니처 컬러 반영.

**검증 노트**
- 초기 데이터를 클라이언트에서 fetch하던 원안을 서버 컴포넌트로 바꿨다. 그러자 앞선 리뷰에서 넘어온 지적 3건(없는 slug를 빈 화면으로 렌더링, slug 인코딩, fetch 응답 타입 단언)이 개별 대응 없이 한꺼번에 사라졌다 — 증상마다 방어 코드를 붙이는 대신 데이터 진입점을 옮긴 판단이다.
- 서버 컴포넌트와 API Route가 각자 mock JSON을 읽지 않도록 조회 함수를 `src/lib/data.ts` 한 곳으로 모았다. 응답 계약을 그대로 유지했으므로, Task 2에서 쓴 테스트를 한 줄도 고치지 않고 통과하는 것으로 리팩터를 검증했다.
- 리팩터 과정에서 "왜 이렇게 묶었는지"를 설명하던 주석이 사라진 것을 리뷰에서 발견해 되살렸다.

### Task 6 — 스크롤 스토리
`docs/mockups/a-depth2-scroll-tour.png` 기반. 투어 도시 궤도 → 트랙 리스트 → 갤러리로 이어지는 스크롤 섹션 구현.

**검증 노트**
- 커버플로우는 드래그로 커버를 넘기는데, 커서가 좁은 띠 영역을 조금만 벗어나도 드래그가 그 자리에서 끊겼다. 포인터 캡처로 고치면서 함정을 하나 만났다 — 누르는 즉시 캡처하면 이동 없는 단순 클릭까지 캡처에 걸리고, 그러면 브라우저가 click을 캡처한 요소로 재타깃하는 탓에 커버 버튼의 클릭이 죽는다. 이동 임계값을 처음 넘는 순간에만 캡처하도록 두어 드래그와 클릭을 모두 살렸다.
- 갤러리 뒤 조명 먼지는 처음에 커스텀 파티클 셰이더로 직접 짰다(파티클 220개, 하이드레이션 불일치를 피하려는 결정적 난수, 프레임마다 수동 좌표 갱신). drei의 `Sparkles`가 정확히 이 용도라 91줄이 16줄로 줄었다. 두 궤도 씬이 따로 갖고 있던 원 좌표 생성 함수도 공용 모듈로 합쳤다.
- 갤러리 이미지는 외부 URL 방식을 1차에서 시도했다가 철회했다 — 원본이 요청 크기보다 작으면 레터박스가 섞이고, 고정 식별자가 아니라 같은 주소가 시간이 지나면 다른 사진을 가리키며, 라이선스도 NC/ND가 섞여 있었다. 로컬 저장 + 출처 파일 방식으로 바꿨다.

### Task 7 — B탭 로그인 + 인증 가드 (TDD)
`docs/mockups/b-login.png` 기반. 하드코딩 계정 검증 로직과 라우트 가드를 TDD로 구현. 미로그인 시 대시보드 접근 차단.

**검증 노트**
- 라벨과 입력 필드가 프로그래밍적으로 연결돼 있지 않았는데도 lint는 조용히 통과했다. 설치된 lint 설정의 규칙 목록을 직접 열어 확인한 결과 접근성 규칙을 6개만 켜고 라벨-컨트롤 연결 규칙은 아예 없었다. 이후 태스크에서는 접근성을 자동 도구에 기대지 않고 직접 챙겼다.
- 브랜드 컬러 위 흰 텍스트가 3.41:1로 AA에 미달한다는 것을 발견했다. 한때 "폰트를 굵게 하면 큰 글자 기준이 적용된다"고 판단했으나 기준(24px 일반 또는 18.66px 굵게) (현재 텍스트는 14px) 을 잘못 적용한 것이라 정정했고, 실제로 통하는 선택지는 표면 색을 어둡게 하거나 텍스트를 어둡게 하는 둘뿐임을 정리했다. 승인된 설계 색이라 화면 하나가 아니라 디자인 시스템 차원의 결정으로 보고 보류했다.
- 시각 검증용 Playwright 을 활용해 미로그인 차단 · 오답 인라인 에러 · 로그인 성공 이동 · 로그인 상태에서 로그인 화면 재방문, 네 시나리오를 스크린샷과 콘솔 로그로 확인했다.

### Task 8 — B탭 대시보드
`docs/mockups/b-dashboard.png` 기반. 사이드바(메뉴 5개 — 대시보드만 실 화면, 무대 연출은 Task 9 자리표시, 나머지 3개는 Coming soon), 메트릭 카드 3종, 도시별 예매 차트(Recharts). 설계 보완으로 아티스트 선택기를 추가해 6팀의 지표를 전환할 수 있게 했다 — 선택 상태를 URL 쿼리(`?artist=`)에 두어 대시보드가 서버 컴포넌트로 남는다.

**검증 노트**
- **로그인에 성공해도 로그인 화면으로 되돌아오는 버그**를 프로덕션 빌드 검증에서 발견했다. 로그인 화면에 있는 B탭 링크가 대시보드를 미인증 상태로 프리페치하고, 그때 받은 리다이렉트 응답이 클라이언트 라우터 캐시에 남아 로그인 성공 후의 이동이 네트워크 요청 없이 그 캐시를 따라간 것이었다(클릭 이후 로그인 요청 외에 아무 요청도 없다는 점으로 확인). 현재 라우트만 비우는 방법으로는 해결되지 않아 전체 내비게이션으로 캐시를 통째로 버리게 고쳤고, 프리페치 정책 자체는 브랜치 범위를 넘는 구조 문제로 따로 기록했다.
- 리뷰에서 지표 조회 함수가 URL에서 온 값으로 객체를 그냥 인덱싱해 **프로토타입 체인을 탄다**는 것을 찾았다. 특정 키는 함수를 반환해 500이 되고, `__proto__`는 빈 객체를 정상 응답인 척 200으로 돌려준다. 서버에 직접 요청해 재현한 뒤, 두 호출부가 모두 지나가는 공용 함수 한 곳에 소유 속성 검사를 넣고 프로토타입 키 4종에 대한 테스트를 추가했다. 같은 리뷰에서, 위 로그인 수정이 이전에 넣어둔 이중 제출 잠금을 풀어버린 것도 함께 잡았다.
- 명암비를 실측하다 **측정 자체의 함정을 두 개** 발견했다. Tailwind v4의 계산값이 `oklab`/`oklch`/`lab` 표기로 나오는 탓에 숫자만 뽑아 쓰면 대비가 2~3배로 부풀려지고(첫 측정이 실제로 그랬다), SVG 텍스트는 `color`가 아니라 `fill`을 재야 한다. 세 표기를 직접 변환하고 알려진 값으로 교차검증한 뒤 재측정해 20개 중 18개 통과를 확인했으며, 남은 2건은 Task 7에서 보류한 바로 그 브랜드 색 조합이었다. 같은 맥락에서, Y축을 숨긴 데다 값 라벨도 없어 수치를 읽을 방법이 아예 없던 차트에 막대 값 라벨과 키보드 툴팁을 넣었다.

### Task 9 — 무대 연출 3D 툴
`docs/mockups/b-stage.png` 기반. R3F 무대 씬 + 우측 컨트롤 패널(조명 프리셋, 조명 on/off, 카메라 앵글 전환).

**검증 노트**
- 원안(컴포넌트 지역 상태)대로면 조명 설정이 새로고침 때 사라지고, 대시보드의 무대 미리보기 카드와도 공유되지 않는다. 브라우저 저장소를 외부 스토어로 구독하는 방식(`useSyncExternalStore`)으로 바꿔 두 화면이 같은 스냅샷을 읽게 했다. effect 안에서 상태를 되돌려 넣는 방식은 React 규칙에 걸리는 데다, 첫 프레임이 기본값으로 그려졌다가 뒤늦게 바뀌는 문제도 있었다.
- 저장된 값을 타입 단언으로 그대로 읽던 코드는 검증이 아니라 선언일 뿐이었다. 예전 스키마로 남은 값이 새로고침 때 그대로 복원되고, 카메라 앵글이 프리셋 밖의 값이면 조회가 실패해 화면이 깨진다. 형태를 검사한 뒤 기본값으로 폴백하도록 고쳤다. 테스트 러너가 node 환경이라 3D 컴포넌트를 import할 수 없어, 상태 로직을 `src/lib/stageState.ts`로 분리한 뒤에야 깨진 JSON · 모양 불일치 · 알 수 없는 앵글까지 테스트로 덮을 수 있었다.
- 설계의 스와치 3개 대신 아티스트 6팀의 시그니처 컬러를 팔레트로 썼다. 색 목록이 데이터 한 곳에서만 나오고, 무대 툴이 대시보드와 같은 아티스트 선택(`?artist=`)을 그대로 이어받는다. 접근성 쪽에서는 폼 컨트롤이 아닌 토글 버튼을 감싸고 있던 라벨을 걷어내고, 눌림 상태를 속성으로 노출했다. (aria-label)
